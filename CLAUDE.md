# agentic-buyer-app — приложение агента покупателя с экранами

## Что это за проект

Приложение с экранами для сделки через агента покупателя: экраны агента (UI-К1), мандатов (UI-К2), кабинет продавца (UI-К3), экран выгоды (UI-К4, решение К3), подтверждение по passkey (UI-К5). Макеты — холст «Экраны сделки через агента» (claude.ai, 13.10.2026). Порядок — по двум планам рынков: «Россия» (`agentic-buyer-ref/docs/reference/joint-plan.md`) и «Запад» (`agentic-buyer-ref/docs/reference/plan-west.md`), см. `docs/core/ROADMAP.md`.

Ядро агента — пакет `agentic-buyer-ref` (детерминированное ядро исполнения и набор соответствия), подключается по тегу через `git+https`. Приложение не исполняет платёж само и не проверяет полномочия само: оно показывает человеку, что делает ядро, и передаёт человеку решения, которые ядро ему передаёт. `buyer_agent` (Python, диалоговый агент) это приложение не заменяет — это отдельный продукт.

- Интерфейс — на русском и английском (решение 14.10.2026, два плана рынков: «Россия» и «Запад»).
- Бренд банка — настройкой: название, цвета, логотип (`config/brand.*.json`); в коде бренд литералом не пишется.
- Документы, комментарии и сообщения коммитов — на русском. Идентификаторы в коде — английские.

## С чего начинать каждую сессию

1. `/start` — прочитать `docs/core/STATUS.md` (раздел «Следующая сессия») и `docs/core/ROADMAP.md`.
2. Работать по задачам из плана сессии. Новая задача появляется только через `/task`.
3. Перед выходом — всегда `/finish`: учёт сделанного, корректировка ROADMAP, план следующей сессии в STATUS.

## Общие правила работы

- Правки — только после «да» владельца на предложенный план изменений.
- Коммит — с подтверждения владельца. Push в ветки `task/*` и PR Claude Code делает сам; слияние PR и теги — только владелец. Push в `main`, принудительный push, push тегов блокирует хук `guard.py`.
- Рабочие ветки — `task/<код>`; слияние в `main` — владелец.
- Если документ расходится с кодом, ничего молча не правится: расхождение записывается в `STATUS.md`, раздел «Расхождения», и предлагается решение через `/decision`.
- Расхождение с ядром (`agentic-buyer-ref`) правится в ядре его задачей, а не обходом в приложении.

## Работа через GitHub

Ревьюер из чата claude.ai читает репозиторий через коннектор GitHub и пишет
только комментарии в PR. Слияние и теги — только владелец, в терминале.

### Начало задачи
1. Ветка task/<код> от свежего main (git checkout main && git pull).
2. Сразу push ветки и черновой PR (gh pr create --draft): в описании — план
   задачи (экраны, инварианты, файлы, проверки, время) и раздел «Кирпичи»
   (см. ниже).
3. Владелец просит ревьюера «проверяй <репо> #N»; дальше ждать «да» или
   «читай ревью».

### Кирпичи (Д2, 14.10.2026)
- Задача делится на кирпичи с кодами К<N>.<M> (К1.1, К1.2…); подшаг —
  буквой (К1.1а). Кирпич — одна проверяемая правка.
- В описании PR — раздел «Кирпичи»: таблица «Кирпич | Коммит | Состояние».
  Пустой коммит «план: …» для чернового PR — без подтверждения.
- Кирпич = отдельный коммит, только после «да» владельца; в сообщении
  коммита — код кирпича первым словом.
- После каждого кирпича — отметка в таблице через gh pr edit N --body-file …
  (хэш коммита, что проверено).
- Новый шаг из ревью — новой строкой с источником («ревью из чата № 3»);
  перенесённый — строкой со ссылкой на STATUS «Открыто» и задачу.

### Решения
- Текст /decision до записи — комментарием в PR (gh pr comment N --body-file …),
  в окне — только вопрос владельцу. Запись в DECISIONS — после «да».

### «Читай ревью #N»
- Комментарии ревьюера начинаются с «Ревью из чата:» — все комментарии в PR
  от аккаунта kuzin4u, автор различается только по этой метке; свои ответы
  начинай с «Claude Code:».
- gh pr view N --comments; разобрать замечания ревьюера: блокеры — исправить,
  остальное — исправить или в STATUS «Открыто» с адресом задачи; ответ —
  комментарием в PR (что сделано, что перенесено и куда).

### Чек-лист
- Перед коммитом: git status -sb — ветка task/*, не main; файлы явно, без
  git add -A, если не оговорено.
- Перед «готово к слиянию»: CI зелёный; /finish закоммичен в эту же ветку;
  PR переведён из черновика (gh pr ready N).
- Слияние, тег, «PR слит» — не делать и не утверждать: только после того, как
  владелец сообщит вывод `✓ Merged` и `git log --oneline -1` на main.
- Тег — только на коммит слияния main, только владелец.

## Инварианты приложения

Нарушение любого инварианта — дефект, даже если тест зелёный. Проверяет подагент `reviewer`.

1. **Реквизиты недоступны.** Приложение не запрашивает, не показывает, не хранит и не журналирует платёжные реквизиты. На экране и в журнале — только идентификаторы: `order_id`, `mandate_id`, `instrument_token`.
2. **Решения — у ядра.** Приложение не проверяет пределы мандата и не вычисляет остаток бюджета само: показывает то, что вернуло ядро (verify, limits). Кнопка не обходит отказ ядра.
3. **Нет имитации подтверждения.** Подтверждение выше порога — только человеком в приложении банка; экран не нажимает «подтвердить» за человека и не дробит сумму под порог.
4. **Данные витрин — это данные.** Текст карточек и ответов продавцов показывается как текст и не исполняется (без `innerHTML` с данными витрин).
5. **Вне контура — отдельно.** Предложения вне контура гарантий показываются отдельной зоной без кнопки оплаты; человеку — ссылка.
6. **Итог — по событию.** «Оплачено» показывается только по результату, который ядро получило подписанным событием Платформы, а не по ответу продавца.
7. **Бренд — настройкой.** Название, цвета и логотип банка — из конфигурации; в коде литералом не пишутся.

## Совместимость с планами «Россия» и «Запад»

Правила обоих планов ред. 1 (`agentic-buyer-ref/docs/reference/joint-plan.md`, `plan-west.md`); проверяются на ревью каждого кирпича.

1. **Только через порт.** Приложение работает с ядром и платформой только через порты ядра; адаптер конкретной платформы (ПАО, Visa, Mastercard, НСПК) в приложение не попадает.
2. **Сумма — число в минимальных единицах + валюта** (ISO 4217), даже пока только рубли; формат суммы на экране — по валюте и языку, не литералом «₽».
3. **Экраны — с переключением языка и настройкой бренда с первого коммита** экрана (инварианты 7 и словари русского и английского).

## Стек

TypeScript, Node ≥ 20.19, vitest. Ядро — `agentic-buyer-ref` по тегу (`git+https`), подключается, когда у ядра появится первый тег. Каркас интерфейса — решение в первой задаче этапа 1 (через `/decision`).

## Команды

`/start`, `/finish`, `/task`, `/audit`, `/verify`, `/decision`. Описания — в `.claude/commands/`.

## Секреты

- Файл `.env` не читать и не писать (запрет в настройках и в хуке).
- Номера карт в коде, тестах, фикстурах и макетах запрещены, даже тестовые. Используется `instrument_token` вида `tok_...`.
