### П1. Отдельное приложение, ядро — пакетом
- **Решение:** agentic-buyer-app — отдельное приложение с экранами на TypeScript. Ядро агента — пакет `agentic-buyer-ref` по тегу (`git+https`). Интерфейс — на русском и английском (уточнение владельца 14.10.2026, два плана рынков); бренд банка (название, цвета, логотип) — настройкой. `buyer_agent` (Python) приложение не заменяет.
- **Почему:** экраны сделки (холст 13.10.2026) показывают банку и продавцам поведение добросовестного агента; ядро уже проверяется набором соответствия, приложение его не дублирует.
- **Что меняет:** структура репозитория, зависимость от ядра, конфигурация бренда.
- **Отменяет:** —
- **Принято:** владельцем 14.10.2026 (служебная сессия agentic-buyer-ref, PR #24).

### П2. Демо-стенд: состав и границы
- **Решение:**
  1. Демо-стенд — тестовый интерфейс приложения, не каркас экранов и не публичный контракт: `src/demo/`, запуск `npm run demo` (`tsx`); стенд Платформы `createStand`, `createMerchants` (эмуляторы банка, эквайрера, токен-сервиса, витрин; экран мандатов банка UI-К2; страница УПК) и настоящий агент через `createAgentCore`.
  2. Только `127.0.0.1`; сервер — `node:http`, страницы — статические HTML и JS без библиотеки интерфейса, лента — SSE. Данные витрин и ответы продавцов — только `textContent` (инвариант 4). Язык ru/en и бренд из `config/brand.*.json` с первого коммита экрана (правило совместимости 3). Эмуляторы на экранах помечены как эмуляторы.
  3. Зависимости — devDependencies, `git+https`: Платформа `#v0.40.0` (тот же тег, что у агента) — уточнено дополнением 3; агент `#4a4ee7c` — по коммиту, не по тегу: отступление от П1 «ядро по тегу» до первого тега агента (Р-39).
  4. До передачи kuzin4u/agentic-buyer-ref#105 (`exports`, `types`, `prepare`) — глубокий импорт `agentic-buyer-ref/src/agent/compose.ts` через `tsx` и vitest; внутренний путь агента, обход в STATUS «Открыто»; снимается кирпичом подъёма коммита агента. Сборка контура стенда — в приложении (`createAgentCore` + `createStand` + `createMerchants`, ОПКЦ — асинхронно через `POST /adp/v1/decide` стенда); экспорт контура у агента не просим (Р-1236 п. 4).
  5. Демо-экран не подменяет решения ядра и человека: подпись поручения — человеком на экране мандатов банка стенда; подтверждение — человеком на странице УПК, код — в панели «эмулятор SMS банка»; `issuer.sign` и `issuer.confirm` — только в автотестах (инварианты 2, 3; Р-1236 п. 2–3).
  6. Выбор библиотеки интерфейса для экранов приложения (UI-К1 и далее) — отдельным решением этапа 1.
- **Почему:** Р-1233 — владелец и банк видят работу настоящих агента и Платформы на экранах; демо не предрешает каркас UI-К1 и не ждёт тега агента.
- **Что меняет:** `package.json` и lockfile (агент, Платформа, `tsx`), `src/demo/`, `npm run demo`; ROADMAP ред. 3; STATUS «Открыто»; CLAUDE.md, раздел «Стек».
- **Отменяет:** — (П1 «ядро по тегу» — временное отступление по п. 3, до тега агента).
- **Принято:** владельцем 05.11.2026 (PR #2, проект — #issuecomment-6654924943; ответы на вопросы плана — Р-1236, #issuecomment-6654739769).

- **Дополнение 2 (05.11.2026, К2.2б):**
  - **Решение:** к п. 1–2. Код, сумма и уточнение в строке события операции на мониторе демо-стенда:
    - код отказа — из ответа ADP стенда на сообщение эквайрера в сборке демо-стенда (`decide`): из ответа берутся только решение и причина; само сообщение эквайрера не читается и не хранится (его составляет эмулятор продавца, в нём инструмент);
    - чей предел при `LIMIT_EXCEEDED` (CLIENT — лимит клиента в банке, MANDATE, INSTRUMENT) — из уведомления банку `client.limit_declined` (ПИ-8), которое банк стенда получает фоновым проходом; подпись «превышен лимит клиента в банке» — только при CLIENT, иначе нейтральная;
    - сумма — только у ядра агента: у одобрения — операция, которую ядро прочитало по событию; у отказа — итог корзины CART ядра (ядро на отказе операцию не запоминает); со слов продавца — ничего;
    - реквизит и инструмент не читаются и не выводятся (инвариант 1).
  - **Почему:** событие Платформы `operation.declined` кода причины не несёт, а ядро агента на отказе операцию не запоминает (находка К2.2б, Р-1258). Сумма из сообщения эквайрера — со слов продавца (ревью reviewer К2.2б, блокер № 1).

- **Дополнение 3 (06.11.2026, К1.1 DEMO-2 ч. 1):**
  - **Решение:** к п. 3. Тег стенда Платформы у демо-стенда приложения:

Протокол агента со стендом — ПАО; если ПАО не менялся, контур демо-стенда на соседней минорной версии ведёт себя так же.
