# Термины

Полный словарь — в ядре (`agentic-buyer-ref`, `docs/core/GLOSSARY.md`). Здесь — термины экранов и их названия в интерфейсе на английском (русские — как в первом столбце).

| Термин | В интерфейсе | Значение |
|---|---|---|
| Агент | Agent | Программа, действующая по поручению клиента в пределах мандата |
| Мандат намерения | Mandate | Задача и пределы: предмет, сумма, срок, категории |
| Мандат корзины | Cart approval | Согласованные состав и стоимость заказа |
| Порог подтверждения | Confirmation threshold | Сумма, выше которой покупку подтверждает человек в банке |
| Контур гарантий | Covered by payment system guarantees | Продавцы, у которых оплата идёт с признаком агентской операции |
| Вне контура | Not covered | Предложения, по которым агент не платит, а передаёт ссылку |
| Экран выгоды | Savings screen | UI-К4: что человек получил от сделки через агента (решение К3) |
| Пульт | Console | Пульт DEMO-2 по модели 1.23: Ход, Контроль, Интерпретатор, Журнал — на шине демо-стенда (Р-1318, Р-1426) |
| Эмулятор клиента | Client emulator | Модуль сборки демо-стенда, который в режиме «Авто» подписывает поручение и корзину и подтверждает запрос за клиента; только при `DEMO_FAULTS=1`, каждое действие помечено (П5) |
| Решения людей: Авто / Вручную | Human decisions: Auto / Manual | Режим пульта: «Вручную» — решения клиента принимает человек на экране мандатов банка и странице УПК (по умолчанию); «Авто» — эмулятор клиента, только при прогоне тестов (П5) |
| На стенде не проверяется | Not checked on the stand | Статус правила справочника 89, которое пульт на стенде не проверяет; не «норма» (Р-1426) |
| en — после MVP | en — after MVP | Пометка правила справочника 89 без английского текста (П6) |
| Драйвер нарушителя (ПР) | Violator driver (ПР) | Модуль сборки демо-стенда, который разыгрывает нарушения агента вида «ПР» (Н-01, Н-05 ПР, Н-06…Н-09) ключом агента приложения и помечает каждое на стенде (`stand.demo.mark`); только при `DEMO_FAULTS=1` (П7) |
| Принцип | Principle | Установка клиента, по которой агент выбирает варианты: «надёжное исполнение», «местный производитель», «ближе», «дешевле». Перечень по умолчанию — данными в `config/principles.default.json`, это стартовые установки, а не закрытый справочник (П32) |
| Профиль предпочтений | Preference profile | Принципы клиента вместе с их порядком важности. Живёт в приложении; на Платформу и продавцу не уходит, банк его не подписывает (П32, Р-1615) |
| Порядок важности | Order of importance | Перестановка подмножества принципов: клиент переставляет пункты и выключает их — **кроме «надёжного исполнения»**, его можно только переставить (П32 доп. 1). Порядок не по правилу — `PRINCIPLES_ORDER_INVALID` (400). Экрану приходит только `rank`, веса остаются на сервере (правка 6 канвы) |
| Роль принципа | Principle role | Пометка пункта в `config/`: `execution` или `price`. Правила системы (ст. 19, «исполнение не выключается») ищут пункты по роли, а не по коду, поэтому переименование кода правило не снимает (П32 доп. 1) |
| Подписанная версия профиля | Signed profile version | Порядок, подтверждённый жестом на экране: хэш показанного и провенанс нажатия (правило 1 К-Б, П26). Версии неизменяемы и нумеруются по возрастанию; пока подписи нет — `signed: null`, и выбор идёт без принципов |
| Ст. 19 — вес исполнения не ниже веса цены | Article 19 — fulfilment weighs no less than price | Правило системы: порядок клиента принимается как есть, но вес цены сервер выше веса исполнения не поднимает — и говорит об этом строкой под списком. Держит сервер, не экран (П32, правило 3 К-Б). Это норма, а не настройка клиента: обойти её нельзя ни порядком, ни выключением пункта, ни переименованием кода в `config/` |
| Продавец | Merchant | Лицо, с которым человек заключает сделку: получатель платежа, сторона спора, предмет пределов поручения. Код вида `MER-7001` (`merchantId` ядра, `merchant_id` ПАО). Решение владельца 22.11.2026 (**Р-1727**) |
| Магазин (витрина) | Shop | Витрина продавца — источник карточек каталога. У одного продавца витрин может быть несколько. Код вида `SHOP-1042` (`CatalogShop.id`, `shopId` ядра). Решение владельца 22.11.2026 (**Р-1727**) |
| Продавец ≠ магазин | Merchant is not a shop | Два **разных** понятия, а не одно слово в двух видах, и признак различения — **разные коды**: совпадение значений в фикстуре это ошибка, а не упрощение (блокер ревью К2 № 2 ВР-1: `shop.id` равнялся `merchantId`, и подмена одного на другое не краснела ни в одной проверке). Переименований в ядре не требуется: `CatalogShop` и `merchantId` названы верно каждый по своему понятию. На экранах (**ВР-8…ВР-10**) человеку показывается **продавец** там, где речь о сделке, деньгах, пределах и споре, и **магазин** там, где речь об источнике карточки (Р-1727) |
| Запись протокола П-NNN | Protocol record П-NNN | Запись протокола пульта (модель 1.23, раздел 1.10; П-6.1а): нарушение, сработавшая гарантия или созревшее предупреждение с номером `П-001`, `П-002`… по порядку появления — одинаковым в ru и en. Одна остановка — одна запись; записи протокола — записи акта ACC-1 (`Acc1Record`). Статусы: открыто, отреагировано, упреждено реакцией, снято само, закрыто, остановлено гарантией |
