## Открыто

- **Правило вердикта — привязка записи журнала сбоев стенда к объекту (П-3.2г; ревью П-3.2в № 3, 4; решение владельца — отзыв PR #9 «(чат, 11.11) — ответ на план П-3.2г»):** уровни по старшинству, решает первый, на котором нашёлся кандидат: **операция** (`op_ref`) → **запрос подтверждения** (`confirmation_id`) → **заказ** (`order_id` или `order_ref` — номер заказа в запросе реквизита; при `shop_id` в записи — только транзакции, где заказ с этим номером был у этой витрины; обращений к витрине по заказу нет — транзакция остаётся кандидатом) → **поручение корзины** → **поручение-намерение** → **поручение без покупки**. Кандидатов на уровне несколько — запись ко всем, но статус условия поднимается **не выше «ждёт»** с пометкой «конфликт звеньев»; привязка только номером заказа к транзакции с конфликтом звеньев — так же. На уровнях корзины и намерения учитываются и поручения транзакции с конфликтом звеньев (`linkConflict`) — такая привязка тоже неточна. **Причина** (повторное ревью П-3.2г № 1, принято владельцем): у транзакции с конфликтом звеньев корзина и намерение не заданы, и запись журнала с одним только поручением одной из конфликтующих корзин ни к чему не привязывалась — уходила в сводный статус, где ограничения «не выше „ждёт“» нет, и давала ложное «нарушено». Это тот же класс ложного «нарушено», что ловит окно Б, а не частный случай. Не нашлось — запись системы (сводный статус; вопрос № 12 — до П-11.2). В П-11.5 вердикт читается по этому правилу (код — `objsOfEntry`, `src/pult/engine.ts`).
- **Ревью П-3.2г (reviewer):** блокеров нет; № 1 (пометка только с поручением одной из конфликтующих корзин уходила в систему без ограничения — сводно ложное «нарушено»), № 2 (тест «один код» без поручений без покупки на стадиях корзины и оплаты — поломкой по С3 проверено, что теперь краснеет) — исправлены. **Адрес П-9:** № 3 — у Н-02 нет `shop_id`, уровень заказа старше поручения: `order_ref` нашей покупки с чужим `mandate_id` в записи даёт «нарушено» у нашей (на стенде номера `ORD-` + 8 hex, совпадение маловероятно) — исключать кандидата при противоречащем `mandate_id` или считать неточной; № 4 — ограничение «не выше „ждёт“» только в `raise`, R31 по сроку в `standConds` его не знает (сейчас недостижимо: поздний итог несёт только `op_ref`); № 5 — живой тест П-01 (`since` = время события) хрупок при сдвиге «начало отрезка не раньше предыдущего» — сверять с `max(authorized.at, предыдущий отрезок)`; № 6 — тест «номер заказа с витриной» не проверяет, куда ушла запись (сейчас — сводно R32 «нарушено», вопрос № 12).
- **Ограничение модели пульта — вердикт по журналу сбоев стенда только в пределах окна записей (П-3.2в, повторное ревью № A; решение владельца, чат 11.11):** окно ленты пульта и шины конечно (шина — 1 000 записей, лента пульта — 20 000), журнал стенда растёт без предела.
