```

```

Склонировали заново — пункт 1.1 всё равно выполняется (перевод на тег), пункт 1.2

### 1.1. Перевод копии на тег `v0.1.1`

```
cd ~/repos/agentic-buyer-app-run
git status -sb                       # ждём: чисто; есть правки — разобрать до перевода
git fetch --tags origin
git switch --detach v0.1.1

```

Отсоединённая голова (`--detach`) выбрана сознательно: приёмка идёт именно на теге,

`git checkout main && git pull` даёт сейчас тот же коммит, но тег надёжнее (`main`
уедет вперёд в следующей задаче, тег — нет).

### 1.2. Проверка доступа к закрытым зависимостям по https

Зависимости `agentic-buyer-ref` и `agentic-ps-platform` ставятся по `git+https`
из закрытых репозиториев проекта (`README.md`, «Запуск»; `package.json`). Проверка —
до `npm ci`, чтобы не ловить «404 при верном токене» из середины установки (Р-1574):

```
git ls-remote https://github.com/kuzin4u/agentic-buyer-ref.git v0.1.0 >/dev/null && echo "агент: доступ есть"
git ls-remote https://github.com/kuzin4u/agentic-ps-platform.git v0.48.0 >/dev/null && echo "Платформа: доступ есть"
```

Обе строки напечатались — доступ есть. Отказ (403/404) — посмотреть, какие подмены
адресов настроены. **Токен лежит в имени настройки, а не в значении** (`ci.yml:42–44`:
секция называется `url.https://x-access-token:<токен>@github.com/`), поэтому
`--name-only` применять нельзя — он напечатает именно токен. Печатать только значения:

```
git config --global --get-regexp '^url\..*\.insteadof' | awk '{print $NF}'
```

Ждём три строки — `https://github.com/`, `ssh://git@github.com/`, `git@github.com:`;
токен в вывод не попадает. Этот вывод можно прикладывать к замечанию, вывод без `awk` —
нельзя.

Нужны три формы одного адреса — `https://`, `ssh://git@`, `git@github.com:` (Р-1566,
`ci.yml:42–44`): без форм `ssh` npm молча уходит на ssh, и настоящая причина прячется
за отказом по ключу. Настраивать подмены — вне этой инструкции (секреты); правка —
`! git config …` в окне сессии владельцем.

## 2. Запуск стенда и пульта

Порт **8787** — один сервер экранов (монитор, пульт, дашборды). Остальные части стенда
(ПАО, витрины, экран банка, страница УПК) слушают **случайные свободные порты** —
их адреса печатает терминал при запуске (`src/demo/main.ts`, `src/demo/stand.ts`).
Стенд слушает только `127.0.0.1`.

### 2.1. ACC-1 — режим учебных сбоев

```
cd ~/repos/agentic-buyer-app-run
lsof -nP -iTCP:8787 -sTCP:LISTEN     # пусто = порт свободен
DEMO_FAULTS=1 DEMO_PORT=8787 npm run demo
```

В выводе должна быть строка **«режим сбоев: вкл. (DEMO_FAULTS=1) — прогон тестов пульта,
срок подтверждения 45 с; для показа людям не включать»** (`i18n.ts`, `cli.faults`; число
печатается фактическое — `order_hold_sec` стенда). Нет этой строки — флаг не принят:
включённым считается **только значение `1`**; `true`, `0` и пустая строка — выключено
(`src/demo/flags.ts`, Р-1527).

`DEMO_ACTIONS=1` для ACC-1 **не нужен**: в режиме сбоев действия кнопок реакции есть
и так (`src/demo/stand.ts:248` — `actions: faults || actionsOnly`), строка «режим показа»
при этом не печатается (`src/demo/main.ts:28`). Выставлять его вместе с `DEMO_FAULTS=1` смысла нет
и вреда тоже.

Прочие флаги: `DEMO_LANG=ru|en` — язык вывода и страниц по умолчанию;
`DEMO_BRAND=<файл>` — бренд (по умолчанию `config/brand.demo.json`).

Адреса (при `DEMO_PORT=8787`):

| Экран | Адрес | Зачем на приёмке |
|---|---|---|
| Пульт | `http://127.0.0.1:8787/pult?lang=ru` | вкладки «Ход», «Контроль», «Интерпретатор», «Журнал»; кнопки реакции; «Собрать отчёт» и выгрузки акта |
| Монитор | `http://127.0.0.1:8787/?lang=ru` | кнопки сюжетов, блок «Поломки» (взвод сбоев «П»), «Авто»/«Вручную» эмулятора клиента, ссылки на банк и витрины |
| Интерпретация | `http://127.0.0.1:8787/dash/interpret?lang=ru` | лента простыми словами (нужна для К1.4; на ACC-1 — по необходимости) |
| Контроль | `http://127.0.0.1:8787/dash/control?lang=ru` | прогоны против паспортов и вердикт владельца (К1.4) |
| Выгрузка «Контроля» | `http://127.0.0.1:8787/dash/control/acc1.md?lang=ru` | Markdown-таблица прогонов сюжетов (К1.4) |

**Вход на экран банка — по ссылке с монитора.** Ссылка «Экран мандатов банка (UI-К2)»
ведёт на `/bank-login`, который одним переходом создаёт **одноразовую** сессию клиента
банка стенда и переадресует на экран (`src/demo/run.ts:124–125`, `src/demo/server.ts:453–460`).
Условия: переход только со страницы монитора или вводом адреса руками — чужая страница,
`<img>` и предзагрузка сессию не создают (проверка `sec-fetch-site`); ссылка в ленту
и журнал не пишется и на странице монитора не хранится. Поэтому адрес экрана банка
**не копировать** в другую вкладку и другой браузер — нужен новый вход переходом
по ссылке на мониторе. Экран банка **обновляется сам каждые 5 с** (`refresh_sec: 5`
у стенда) — F5 не нужен; с версии стенда v0.48.0 он же показывает местное время (З9).

Страница УПК открывается **только кнопкой на панели сюжета 4**; ссылка вверху монитора
неактивна — «откроется в сюжете 4» (З6).

**Срок входа — два разных срока** (источник: пакет `agentic-ps-platform` **v0.48.0**,
`dist/env/issuer/screen.js`, `STAND_SCREEN_TTL = { login_ttl_sec: 120, session_ttl_sec: 900 }`;
границы проверяет `dist/ui/mandates/session.js`, `checkTtl` — ссылка 1…600 с, сессия
1…3600 с):

- **одноразовая ссылка входа — 120 с (2 минуты).** Переход гасит токен; просроченная
  или повторно открытая ссылка даёт 401 и текст «Ссылка недействительна или устарела.
  Откройте экран из приложения банка ещё раз.»;
- **сессия экрана — 900 с (15 минут)**, в cookie `__Host-bank-mandates`
  (`HttpOnly; Secure; SameSite=Strict`). Истекла — экран отвечает 401 «Войдите через
  приложение банка».

И в том и в другом случае лечение одно: вернуться на монитор и перейти по ссылке
«Экран мандатов банка» заново. На сюжетах с долгим ожиданием (подтверждение 45 с,
срок «Контроля» 15 с) 15 минут хватает с запасом, но при паузе в прогоне вход
придётся повторить. Те же два числа — в памятке прогона v1.3, раздел «Экраны стенда».

Сроки, которые видно на приёмке: подтверждение человеком — **45 с** в режиме сбоев;
порог «идёт к нарушению» — **15 с**; срок ожидания «Контроля» — **15 с после последней
записи прогона**, кнопки вердикта появляются только после него
(`docs/core/demo-walkthrough.md`, раздел «Срок ожидания «Контроля»»).

### 2.2. Что делает человек на ACC-1

25 тестов задания v1.1 (`TEST_CODES` в `src/pult/testtable.ts`): П-01…П-09, Н-01…Н-12,
У-01…У-04. Сюжеты запускаются кнопками монитора, сбои «П» взводятся блоком «Поломки»,
ветки «ПР» идут драйвером нарушителя при эмуляторе клиента «Авто».

**Порядок прогона — как в комментарии в начале `tests/demo/pult-25-live.test.ts`
(строки 5–9):** сначала правильные П-xx; затем сюжеты 4 и 2 в режиме оператора; затем
Н-xx «П» (взвод во время сюжета) и Н-xx «ПР» (драйвер при «Авто»); У-01 — последним
прогоном сюжета `intent`. Между прогонами — ждать кнопок вердикта «Контроля» (≈ 15 с
тишины), иначе оба прогона получат пометку «события Платформы могли попасть в чужой
прогон» (Р-1396 п. 2).

**Главное отличие ручной приёмки от автоматического прогона.** Строки оператора
У-01…У-04 должны выйти **без пометки «автоматический прогон: роль оператора играл тест»**
(`OPERATOR_BY_TEST_LABEL`, `src/pult/acc1.ts:99–103`). Пометку ставит только файл теста
(`operatorByTest: true`); маршрут `/pult/report`, которым пользуется владелец, собирает акт
**без** этого параметра (`src/demo/pult-report.ts:61`) — то есть пометки не будет
автоматически. Чтобы «да» было честным, на У-01…У-04 владелец сам:
клиент отвечает **позже 15 с** (чтобы запись дошла до «идёт к нарушению»), и **кнопки
реакции на пульте нажимает человек**. Эмулятор клиента на этих четырёх строках держать
**«Вручную»** — при «Авто» в акте появится пометка «эмулятор клиента: авто» (`AUTO_LABEL`).
На ветках Н-xx «ПР» «Авто» нужен, и пометки «Авто» / «ПР» там ожидаемы (П5 п. 3, П7 п. 4).

Известные заранее строки: **Н-02 — «не проверено»** с причиной (`KNOWN_NOTES`, П11;
снимется после передачи kuzin4u/agentic-ps-platform#120), **Н-10 — «нет случая»**.
Автоматический прогон 14.11 дал 23 «да», 0 «нет».

## 3. Остановка и проверка, что порт 8787 свободен

1. В терминале стенда — **Ctrl+C один раз** (`cli.stop`: «Остановка — Ctrl+C.»).
   Обработчик SIGINT закрывает эмулятор клиента, сюжеты, драйвер, шину, сервер экранов
   и стенд и **удаляет временные каталоги** (`src/demo/main.ts:42–55`,
   `src/demo/stand.ts:136–146`). Второй Ctrl+C не нужен: повторный вызов игнорируется.
   Дождаться возврата приглашения оболочки; ошибка закрытия печатается строкой
   «демо-стенд: ошибка при остановке».
2. Порт:

```
lsof -nP -iTCP:8787 -sTCP:LISTEN     # ждём: пусто
```

Не пусто — остался процесс: `pgrep -fl "src/demo/main.ts"`, затем аккуратно
`kill <pid>` (не `-9`: при `-9` временные каталоги с ключом агента останутся на диске).

3. Остатки временных каталогов (если стенд падал или его убивали `-9`):

```
ls -d "${TMPDIR:-/tmp}"/demo-keys-* "${TMPDIR:-/tmp}"/demo-state-* 2>/dev/null
```

Нашлись — удалить (`rm -rf <путь>`): в `demo-keys-*` лежит ключ агента стенда.

## 4. Условия безопасного прогона

### 4.1. Что можно запускать одновременно, а что нельзя

| Что | Можно ли | Почему |
|---|---|---|
| ACC-1 и К1.4 **одновременно** | **нельзя** | обоим нужен порт 8787 — вторая команда упадёт на занятом порту; и режимы разные (с сбоями / без), смешивать их в одном акте нельзя |
| живой прогон 25 тестов `PULT_25=1 npm test` | **не во время приёмки** | он поднимает **свой** стенд на своём свободном порту и отказывается работать на 8787 (`ownStandOrFail`, П16 п. 5) — то есть приёмке он не помешает портом, но идёт 6–8 мин под полной загрузкой, а вердикты на приёмке держатся на сроках 15 с и 45 с: загруженная машина даёт ложные пометки раннего запуска |
| `npm run demo` в другой папке | **только без приёмки** | без `DEMO_PORT` берётся свободный порт, конфликта нет, но это второй настоящий агент и второй стенд на той же машине: нагрузка и перепутанные вкладки. На 8787 второй стенд не поднимать никогда |
| `npm test` окна А в `~/repos/agentic-buyer-app` | **не во время приёмки** | живые тесты поднимают стенды на случайных свободных портах (фиксированного 8787 в тестах нет), поэтому порт они не отнимут; но это десятки минут загрузки процессора рядом со сроками приёмки |
| `npm ci` в копии прогона при поднятом стенде | **нельзя** | `node_modules` заменяется под работающим процессом |

Правило одной строкой: **во время приёмки на машине работает только стенд приёмки.**

### 4.2. Какой порт чем занят

- **8787** — сервер экранов копии прогона: монитор, пульт, «Интерпретация», «Контроль»,
  `/bank-login`, выгрузки отчёта. Задан `DEMO_PORT=8787`, закреплён за приёмкой (Р-1477).
- **случайные свободные** — ПАО стенда, витрины продавцов, экран мандатов банка, страница
  УПК; адреса печатает терминал при запуске, в коде они не фиксированы.
- занимать 8787 чем-либо ещё во время приёмки нельзя: пульт и монитор обращаются
  только к нему.

### 4.3. Сколько вкладок пульта (Р-1530)

- **Пульт — ровно одна вкладка.** У вкладки пульта два постоянных потока SSE
  (`/pult/events` и `/pult/feeds`), а браузер держит 6 соединений на адрес: вторая вкладка
  пульта или монитора может **задержать кнопки** (строка в справке пульта — П-9.2,
  `src/pult/help.ts:42`, пояснение — там же в комментарии 39–40).
- Вторая вкладка пульта ломает ещё и выгрузку: снимок отчёта хранится **один**, и собранный
  в другой вкладке снимок делает ссылки первой негодными — 409 `SNAPSHOT_GONE`,
  «снимок устарел — соберите отчёт заново» (Х4б).
- На ACC-1 нужны **две** вкладки: пульт и монитор (кнопки сюжетов, «Поломки», «Авто»).
  «Интерпретацию» и «Контроль» открывать по необходимости и закрывать; больше трёх вкладок
  на `127.0.0.1:8787` не держать.
- Кнопки «ждут» при одном пульте — это повод для пересмотра Р-1530 (запись в «Открыто»):
  отметить в замечаниях приёмки.

### 4.4. Что пишется на диск во время прогона

**В репозиторий и в постоянные каталоги приложение во время прогона не пишет.** Данные
прогона — лента, доска, вердикты, протокол, снимок отчёта — живут в памяти процесса
стенда. На диск пишутся **только два временных каталога** в `$TMPDIR`, оба создаются
при запуске (`mkdtempSync`, `src/demo/stand.ts:149,151`): `demo-keys-*` — ключ подписи
агента (`generateKey`, там же:188) и `demo-state-*` — состояние ядра агента, в том числе
курсор ленты событий. Оба удаляются при остановке Ctrl+C. Платёжных реквизитов в них нет
(журнал агента — в памяти, `MemoryJournal`).

| Что | Где | Что с ним при перезапуске стенда |
|---|---|---|
| лента шины (1000 записей на поток), лента и доска пульта (окно 20 000 записей), ход транзакций | память | **стирается** |
| вердикты владельца в «Контроле» | память стенда | **стираются** (STATUS «Открыто») |
| протокол `П-NNN` и «Журнал действий» | память | **стирается** |
| снимок отчёта для выгрузки акта | память, **хранится один** (`reportAt`) | **сбрасывается** (Х4б, ревью № 1): ссылки прежнего снимка дают 409 `SNAPSHOT_GONE` |
| временные каталоги `demo-keys-*` (ключ агента) и `demo-state-*` (состояние ядра, курсор ленты) в `$TMPDIR` | диск, вне репозитория | **удаляются** при остановке Ctrl+C; при `kill -9` остаются (см. п. 3) |
| выгрузки акта и CSV | **загрузки браузера** (`~/Downloads`), имя `acc1-<время>-<язык>[-excel].<md\|csv>` | на диске остаются — это и есть результат |

Отсюда правило приёмки (Х4б): **выгружать акт сразу после сборки** и сверять время
сборки внутри файла со временем `builtAt` на экране. Перезапустили стенд — прогон
начинается заново, прежние вердикты и снимок не восстанавливаются.

### 4.5. Что сохранить как результат

На пульте, вкладка **«Журнал»** → «Собрать отчёт», затем «Выгрузка»:

1. **Акт ACC-1 — Markdown**: файл `acc1-<2026-11-16T12-34>-ru.md` (имя даёт стенд,
   время — часы шины, UTC; `src/demo/pult-report.ts:26, 63`).
2. **CSV (машинное чтение)**: `acc1-<время>-ru.csv`.
3. **CSV для Excel**: `acc1-<время>-ru-excel.csv` — делитель «;», для региональных
   настроек с «;»; при `en-US` файл ляжет в одну колонку.
4. Те же три файла **на en**: открыть пульт с `?lang=en`, собрать отчёт заново
   и выгрузить (автоматический прогон 14.11 собирал акт в обоих языках).
5. **Номер записи `П-NNN`** — из панели «Журнал» (протокол негативных значений):
   каждое замечание приёмки адресуется номером записи, строкой теста (П-xx / Н-xx / У-xx)
   и меткой прогона. Эти же номера стоят в колонке замечаний акта.
6. Дополнительно для К1.4: выгрузка «Контроля» `/dash/control/acc1.md?lang=ru`
   (сохранить страницей из браузера) — таблица прогонов сюжетов с вердиктами владельца.

Класть всё **вне репозитория** — например `~/Documents/acceptance/2026-11-16/`:
так `git status -sb` в копии прогона остаётся пустым.

### 4.6. Что откатить или удалить после прогона

Откатывать, как правило, нечего: стенд в репозиторий не пишет, а `npm ci` трогает только
`node_modules/` (в `.gitignore`). Проверка:

```
cd ~/repos/agentic-buyer-app-run
git status -sb                       # ждём: «## HEAD (no branch)» и ни одной строки файлов
git clean -nd                        # ждём: пусто (показывает, ничего не удаляя)
```

Если что-то появилось:

- **файлы акта и CSV скачались в репозиторий** — перенести в папку результатов
  (п. 4.5), в репозитории не оставлять;
- **изменился отслеживаемый файл** — `git diff` и затем `git checkout -- <файл>`
  (правки в копии прогона не нужны: замечания закрываются кирпичами на `main`, П16 п. 3);
- `git clean` с удалением (`-fd`) — только после просмотра вывода `-nd`.

`node_modules` удалять не нужно — он понадобится на следующем прогоне; понадобится
место — `rm -rf node_modules` и `npm ci` перед следующим запуском.
