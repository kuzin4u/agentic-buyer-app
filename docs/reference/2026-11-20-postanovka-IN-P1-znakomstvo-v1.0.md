# Постановка ИН-П1 — знакомство, условия, согласия (экраны П1 и П3) · версия 1.0 от 20.11.2026, 20:05

Задача плана после MVP v1.5, строка «ИН-П1 — знакомство, условия, оферта, согласия (П1, П3)», направление «Интерфейс», окно Б, план 3,0 ч (1,5 сессии). Файл кладёт владелец в `docs/reference/`, окно его не правит.

## Функционал простыми словами

Человек впервые заводит агента. На первом экране (П1) он видит три вида агентов — агент банка, свой агент, агент площадки — и таблицу, чем они отличаются для него: кто отвечает за ошибку, где разбирают спор, ищет ли агент у всех продавцов, что будет с поручениями при смене банка. Выбрать можно агента банка или своего агента; агент площадки показан для сравнения и пока недоступен — с объяснением.

На третьем экране (П3) человек читает, что может выбранный агент, и ставит две отдельные галочки: принимает условия и соглашается на обработку данных о покупках. Обе галочки сначала пустые. Пока обе не отмечены, кнопка «Принять условия» недоступна, и экран говорит почему. Согласие записывается так, что его нельзя изменить: с отпечатком ровно того текста, который человек видел, с версией текста, выбранной моделью агента и отметкой, кто нажал. Деньги на этих экранах не списываются, ничего не подключается.

## Тексты П3 по моделям (черновик для `config/`, ru; en — парой)

**М1 — агент банка** (как в канве): покупает только то и на ту сумму, что поручили; дороже порога — спросит, вне поручения — не купит; деньги списывает ваш банк, номера карты агент не видит; купил не по поручению — банк вернёт деньги без разбирательства по существу; все поручения пишутся в журнал, изменить записи нельзя.

**М2 — свой агент:** покупает только то и на ту сумму, что поручили; сделка — напрямую с продавцом, каждую оплату вы подтверждаете сами в своём банке; номера карты агент не видит; за настройку агента отвечаете вы — так и сказано на прошлом экране; все поручения пишутся в журнал, изменить записи нельзя; цена агента — 1 копейка, на стенде не списывается (Р-1661).

Пометка над галочками на обоих наборах: «Условия демо-стенда, не оферта».

Тексты согласий: «Принимаю условия агента»; «Согласен на обработку данных о покупках и передачу их в журнал поручений». Причина недоступной кнопки: «Отметьте оба пункта — без них агент не может работать с вашими покупками». Причина у М3: «Будет после запуска».

## Методы — проект для К-Б v1.1 (§ 5.17–§ 5.19)

До выхода К-Б v1.1 типы помечаются `PENDING_V1_1`, как `notes`, `INTENT_DRAFT_INVALID`, `SESSION_REQUIRED`; сверка с документом — отдельным ожиданием К2.4.

**§ 5.17 `GET /ui/v1/onboarding` — П1.** Без подписи и хэша: на П1 человек ничего не подтверждает.
```json
{ "step": { "n": 1, "of": 8 },
  "models": [ { "id": "M1", "name": "…", "text": "…", "selectable": true,  "why_not": null },
              { "id": "M2", "name": "…", "text": "…", "selectable": true,  "why_not": null },
              { "id": "M3", "name": "…", "text": "…", "selectable": false, "why_not": "Будет после запуска" } ],
  "compare": [ { "row": "LIABILITY", "label": "Кто отвечает за ошибку", "values": { "M1": "банк", "M2": "…", "M3": "…" } } ],
  "action": { "label_by_model": { "M1": "Подключить агента банка", "M2": "Завести своего агента" } } }
```

**§ 5.18 `GET /ui/v1/onboarding/terms?model=M1|M2` — П3.** Карточка, которую человек подтверждает, — с `view` по правилу 1. Хэш считается по модели, версии текстов, перечню пунктов «что может агент», пометке «демо, не оферта» и текстам обоих согласий, на языке запроса.
```json
{ "step": { "n": 3, "of": 8 }, "model": "M1",
  "can": [ "…" ], "demo_note": "Условия демо-стенда, не оферта",
  "consents": [ { "id": "TERMS", "text": "…", "required": true }, { "id": "DATA", "text": "…", "required": true } ],
  "actions": { "accept": { "label": "Принять условия", "why_disabled_until_all_required": "Отметьте оба пункта — …" } },
  "view": { "view_id": "vw_…", "text_version": "p3@1.0", "hash": "sha256:…" } }
```
Сервер отдаёт перечень обязательных пунктов и готовый текст причины; экран только сверяет, все ли отмеченные пункты из этого перечня. Окончательно решает сервер в § 5.19. `model=M3` — 409 `MODEL_NOT_AVAILABLE` (`never`).

**§ 5.19 `POST /ui/v1/consent` — принять условия.**
```json
// запрос
{ "model": "M1", "consents": { "TERMS": true, "DATA": true }, "shown_hash": "sha256:…", "press": { … } }
// ответ 200
{ "consent": { "version": "1", "model": "M1", "at": "…", "by": "human", "text_version": "p3@1.0" }, "next": { "step": 4 } }
```
- Правило 2: `Idempotency-Key`; ключ занимает любой окончательный ответ, включая отказ, кроме `IDEMPOTENCY_REQUIRED` (Р-1633, Р-1635).
- Правило 1: хэш не совпал или текст устарел — 409 `SHOWN_STALE` с новой карточкой.
- Не отмечен обязательный пункт, лишнее поле, неизвестный пункт — 400 `CONSENT_INVALID` (`after_fix`), причина — в журнал, экрану текст по причине.
- `model` М3 или неизвестная — 409 `MODEL_NOT_AVAILABLE` (`never`).
- `by` — из тела не берётся ни в каком режиме (К5 ИН-0); вне режима прогона `human`.
- Без сессии — 401 `SESSION_REQUIRED` (К7 ИН-0).
